# 寻宝小车 · 实时观测台

用于 2026 年江苏省大学生机器人大赛的寻宝小车数据采集与回放工具。浏览器通过 Web Serial 读取小车调试串口，历史测量保存在使用者本机浏览器中。

## 本地启动

使用 Node.js 22.15 或更新版本。在仓库目录运行 `npm run dev`，然后在桌面版 Chrome 或 Edge 中打开 `http://localhost:4174`。项目无运行时 npm 依赖。

## 使用

桌面 Chrome / Edge，HTTPS 或 localhost；默认 115200、8N1、无流控。USB 串口或系统已配对的蓝牙 COM 口均从浏览器设备选择器选择。浏览器不提供通用串口设备名称列表，必须由使用者选择和授权。页面仅接收，不发送控制指令。

- 地图按 ENM 连续车体中心和实际朝向采样显示；不沿赛道吸附、不补造两帧间动作。N 仅作为无 ENM 时的离散节点位置。
- 车头/车尾是物理方向；dir=-1 只改变行驶侧箭头透明度，不使车体旋转 180°。
- 新 ENM.yaw10 是地图朝向；旧日志依赖 PLAN 的明确标定，将 IMU/WF 原始角度换算到地图。没有可靠标定时不显示朝向箭头。
- 地图可拖动、滚轮或按钮缩放；开启跟随后小车位于视角中心。
- 四轮各一张目标/实际速度图，四路激光各一张图，可勾选通道。轮速和激光分别选择左栏、中间（地图与终端之间）或右栏，默认放在右栏顶部，位置自动记忆。四轮位置：A 左上、B 右上、C 左下、D 右下；单位 mm/s。激光按 F/L/B/R（前左后右），0 为无效读数。导出元数据包含四轮位置。
- “重新开始”同步切换记录缓冲区，保持串口连接，把上一次测量保存到 IndexedDB。历史支持播放、命名、删除、导出；默认上海时间名称“测试数据MMDDHHmm”，同名加序号。
- 导出可选择本地目录，生成 NAME.txt 与 NAME/；不支持目录选择或文件选择器正忙时自动下载 ZIP，并显示原因。导出期间禁止重复触发，取消选择后可重试或手动下载 ZIP。CSV 包含接收时间、固件时间及解析数据；metadata.json 包含原始逐行接收时间。文件名自动清理非法字符，磁盘同名输出不会被覆盖。
- 原始导入日志支持 UTF-8、GB18030。回放按设备时间分帧；保留停顿和真实时钟重启，隔离截断/拼接或异常时间戳。终端最多显示 500 行，测量原文持续记录；20 万行自动归档分段；导入单文件上限 50 MB。

## 数据与限制

网页使用 `dist/map.json` 中的数字化赛道地图，包含 138 条线段。原点在左下角，X 向右、Y 向上。地图共有 12×10 个节点，每格 300 mm，节点 ID 为 `y × 12 + x`。

当前工程 `main_square.c` 的 PD_LOG_TICKS=0，ENM 约400 ms；N/IMU约200 ms；W4在转弯时约40 ms。WF直行四轮记录被该配置关闭，所以四轮图在直行时可能空白。18列普通调试行只含左右平均速度，不足以还原独立四轮速度，本站不会伪造补齐。现场动作的可见精度受固件采样频率及定位估计准确度限制。

新固件取消激光置信度筛选，有效 F/L/B/R 检测直接以 `:OK` 标为敌人位置，ENM.T 为当前主要敌人位置；无有效检测输出 0。旧日志中的 LOW 候选仍以虚线区分。q/h 为兼容旧协议保留的字段，页面不把它们显示为置信度。导航目标是 N第7列或 MAT.tgt，255为无目标。FW BUILD 或 IMH/IMU中的 FW 标签显示为地图左上半透明标识；日志未提供时显示未知。

激光位置测试使用固件 `LaserTest` 构建预设，FW BUILD 为 `20261019-LASER-POSITION-DIRECT`。小车放在网格 (6,4)，即 (1800,1200) mm、节点 54；车头朝正北后复位，首个有效 IMU 角度自动标定为北 0°。测试模式禁用电机输出，可手动转动、推动小车，编码器位移与陀螺仪用于更新自身位置，再计算四路激光检测到的敌人位置。重新标零需放回 (6,4)、朝北并按 USER，网页不向小车发送指令。

固件周期输出 `LTEST,<t>,mode=LASER,start=6/4,north10=0,imu=1,enc=1,ready=1,motors=0`。页面显示起点、北为 0° 且顺时针为正的角度、IMU/编码器与就绪状态，超过 2 秒标记过期；`motors=0` 时显示电机禁用。LTEST 只提供模式状态和初始设置，不替代 ENM 连续位姿。ENM.yaw10 保持原地图角度：东为 0°、北为 90°，避免改变历史日志、地图朝向和导出约定。

历史存储属于浏览器站点数据，清理浏览器数据会移除它。存储不可用时页面明确警告并使用内存降级；需导出留档。串口真实硬件连接尚需队友现场验收。

## 开源调研

- [GoogleChromeLabs/serial-terminal](https://github.com/GoogleChromeLabs/serial-terminal)：Apache-2.0，浏览器串口终端参考。
- [atomic14/web-serial-plotter](https://github.com/atomic14/web-serial-plotter)：GPL-3.0，实时绘图和日志交互参考。
- [Chrome Web Serial 官方文档](https://developer.chrome.com/docs/capabilities/serial)：API、设备授权与安全上下文要求。

本站独立实现，未复制上述项目源码，无运行时 npm 依赖。

## 本地开发与验证

运行 `npm test` 验证协议解析、姿态、会话和导出。运行 `node tests/log-validation.mjs "<日志目录>"` 可为目录中最近修改的六个 `.txt` 文件生成本地验证摘要。将日志文件路径作为 JSON 数组传给环境变量 `ROBOT_TEST_LOG_FILES`，可在 `npm test` 中一并验证真实日志导出。

`dist/` 包含完整的网页，可由任意支持 HTTPS 的静态文件服务器托管。此仓库包含网站源码，固件源码另行维护。
